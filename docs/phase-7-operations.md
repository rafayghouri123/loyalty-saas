# Phase 7 reports and exports

Scope: owner/manager overview and O15 reporting. Phase 8 billing/admin/account privacy and Phase 9 hosting/load/device evidence remain separate.

Apply additive migrations `202609260051_reporting.sql`, `202609260052_report_exports.sql` and `202609260053_report_configuration.sql` through the reviewed migration workflow. They add source indexes, scoped RPCs, private export records and a private `loyalty-exports` Storage bucket with no browser listing/read policy. Migration 053 fixes a configuration-variable ambiguity found by staging verification. They do not reset data or create a report cache. Deploy web and worker code together after migrations; regenerate catalog types. If rollback is needed, revert the web/worker feature first and preserve export/audit records. Do not delete source/accounting history.

The owner overview at `/dashboard/[businessId]` and the seven tabs at `/dashboard/[businessId]/reports` query only the active view. Managers see assigned branches; cashiers use staff checkout. Select Today, Last 7 days, Last 30 days or Custom (1–90 calendar days). Presets resolve on the database using business time. Date intervals are half-open UTC boundaries; tables default to 25 rows with 50/100 choices. The programme-version selector applies to purchase-based Overview/Customers/Double slots. Reward filters apply to redemption/cost; shared earning units show N/A for a selected reward. IDs/sort/columns are allowlisted and checked again by SQL.

Refresh explicitly reads committed source data. There is no polling or stale-data fallback. A failed refresh clears old results and shows Retry. All private pages/APIs/downloads use no-store and bypass the service-worker cache. Permission/status locks are held through the read. PostgreSQL reports use a STABLE calculation within one snapshot; related totals and paginated rows agree. `dataAsOf` is the database statement timestamp.

`get_report`, configuration and export RPCs declare a five-second `statement_timeout` as a function setting. PostgREST **hoists** this to the transaction before the main query; do not replace it with `set_config` inside an already-running query. Verify your PostgREST `db-hoisted-tx-settings` still includes `statement_timeout`. [Official transaction settings](https://docs.postgrest.org/en/v12/references/transactions.html#function-settings) explain this boundary. Direct SQL harnesses and the export worker set the timeout in a preceding statement. A blocked-purchase-table test exercises actual cancellation. HTTP returns a retry/narrow-date-range error, never zeros.

Counts/sums use indexed source tables. New members use joined branch; purchase/redemption metrics use actual branch. Returning classification checks prior business-wide qualifying purchases without exposing receipts. Net cohort sales/units reverse original sources regardless of reversal processing date. Rewards includes separately dated purchase/redemption reversal activity rows; Staff shows processing actions. Current outstanding/debt is shown only to owners with All branches. Unknown costs/zero denominators show N/A. Approximate referral visits have a 90-day coverage window; branch visit projections use referrer join branch. Campaign rows keep membership reach, device attempts, accepted/failed/unknown attempts, observed clicks, claims and associated net sales separate. Manual counts never infer WhatsApp delivery/read. Associated sales do not prove incremental revenue.

## Private exports

Export CSV confirms date/branch/report and approved columns. Defaults omit customer/staff identity and always exclude contact/birthday/consent fields. Customers has a separate shared-contact flow: owner or manager with **both** export/contact grants. Owner export creation requires AAL2; owner contact download also requires AAL2. Staff revocation, branch removal, ownership change, unavailable Auth session and expired artifact block execution/download immediately.

Exports are asynchronous: Pending → Processing → Completed / Failed / Expired. The UI has an explicit Check export status button, no polling. A disabled/unhosted worker leaves an honest Pending state. Enable `EXPORT_PROCESSING_ENABLED=true` only on the separate persistent worker and supply its existing restricted database connection, Storage-only service credential, Supabase URL and encryption key/id. The web uses the same encryption key/id but **never** the Storage service credential. No provider messaging flag is needed.

The `report.export_requested` outbox transaction becomes a pg-boss `report-export` job. SQL rechecks current permissions and reserves a five-minute processing lease. Each attempt gets its own immutable storage path; an old worker cannot complete a newer lease. Transient failures retry with backoff, final failures are recorded, and receipts prevent reprocessing a completed artifact. Expired/orphan upload paths are tracked for cleanup. No database locks are held across network uploads.

Report/contact exports fail with Narrow filters above 10,000 rows or 3 MiB. No silent truncation. The worker bounds source rows and CSV UTF-8 bytes, quotes cells, and prefixes formula-like cells even after whitespace/control prefixes. A metadata row includes fixed filters, source timestamp and aggregate definitions; columns ending Paisa remain integer paisa. Account exports are Phase 8, not this bounded report flow.

Artifacts expire 24 hours after request creation. Worker cleanup removes private objects and encrypted links; minimal audit/request history remains. Signed Storage URLs are encrypted with AES-GCM and bound to artifact ID in a private record. The current user-scoped RPC returns ciphertext only to its requester; the web download proxy decrypts/fetches at most 3 MiB from the configured Supabase origin, rechecks permission after fetching, and emits a no-store attachment. It never redirects to or exposes the bearer URL. Authorization events are audited; they do not claim the browser saved/read a file.

## Verification commands

- `./scripts/run.ps1 test`, `test:integration`, `lint`, `typecheck`, `build`.
- `./scripts/run.ps1 test:phase7:browser` for targeted desktop/360px checks; `test:e2e` for the complete suite.
- `./scripts/run.ps1 test:phase7:provider` creates synthetic accounts/businesses in the configured isolated staging project, tests real Auth/PostgREST/Storage and a production web server, then archives test businesses/removes accounts and artifacts. It refuses a project with active customer data. It sends no push/email/WhatsApp/payment.

The local representative plan check demonstrates the branch/date index is available. It is not the section 27.5 sustained 100,000-purchase mixed-load benchmark. Persistent worker supervision, supplier budgets, restore and Pakistan network/real-device evidence remain later release gates.
