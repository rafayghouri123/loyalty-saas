| Criterion | Implementation and evidence |

| Owner calendar, editor and history | O07 has a navigable business-local month calendar, branch/time-labelled slots, same-day draft editor, explicit publish/pause, customer card preview, sample eligible and ineligible purchase, version history and attributed bonus counts. Published versions and historical purchase references are immutable. The authenticated mobile browser flow checks the card preview, calendar date and width. |
| Scheduled server bonus | The database computes base earn first and adds `min(base, promotion bonus cap)` only for an eligible, enabled 2x slot. The effective programme and slot are selected after a single post-lock database clock capture; the local date/time uses the business IANA timezone and a half-open window. A purchase stores the version, base and bonus. |
| Overlap, caps and stale previews | Business-row serialization blocks overlapping enabled slots on the same branch and returns the conflicting slot and branch. The calendar check examines actual local dates, allowing consecutive Monday offers whose date ranges overlap only on other weekdays. The per-member daily cap belongs to the stable promotion across branches/versions, is checked under value locks and is released on full reversal. Two concurrent purchases compete for one slot; only one gets a bonus. Confirmation rechecks the expected effect hash; a changed version, branch, cap or balance returns HTTP 409 with a fresh preview and writes nothing. The staff UI replaces the old preview and requires a new confirmation. A dedicated conflict SQLSTATE avoids the hosted RPC gateway's serialization retry behavior. Local tests cover before/start/inside/end/after, different branch, cap races and rate-version changes, retry, wrong client clock and Rs 250 producing 2 base + 2 promotion points. |
| Referral link and attribution | Codes use 16 random bytes, canonical case-sensitive unpadded Base64URL and global SQL uniqueness. `/r/[code]` returns one generic unavailable page for ineligible destinations. A signed bounded HttpOnly cookie carries the first valid referral through authentication. A separate signed first-party cookie records at most one approximate visit per code/browser/UTC day. Visit rows contain no customer or IP, a worker removes rows older than 90 days, and only the owner sees covered-period totals across all branches. A gateway-only, session-bound grant is consumed by enrollment; direct clients cannot forge claims or read private grants. Existing members, self-referrals and stale attribution do not attach a new inviter. |
| Qualified rewards and fraud signals | Each newly enrolled membership has at most one claim with rules captured at enrollment. The first qualifying purchase within its deadline atomically awards friend and eligible inviter once, without signup bonus. The monthly inviter cap is serialized across rule versions; a capped inviter is suppressed while the friend still earns. Left/suspended inviters pause qualification until they return within the original deadline; anonymized inviters cannot earn. Owner/manager results provide bounded filters, aggregate counts, anonymized friend labels and a shared-phone review signal. The customer sees their own link and status counts. |
| Full reversal and accounting | A full refund compensates purchase, promotion, friend and inviter ledger entries, marks a qualified claim reversed, releases applicable cap usage and cannot requalify that claim. Idempotent retries do not duplicate effects. Both balances reconcile to the ledger. |
| Hosted acceptance | Migrations 026–035 are applied to the isolated staging Supabase project. `scripts/verify-phase4-provider.mjs` created synthetic verified Auth users and an AAL2 owner, exercised real PostgREST/API/browser referral, signed visit deduplication, owner visit totals, slot, stale-checkout conflict with fresh preview and zero write, confirmed checkout, replay and refund, then archived its business and deleted its users. The hosted RPC gateway timed out on expected `40001` errors; dedicated `23P01` conflict signals make overlap and stale checkout return usable HTTP 409 responses. |
