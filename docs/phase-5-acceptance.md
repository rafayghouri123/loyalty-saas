| Criterion | Implementation and evidence |
| --- | --- |
| Installable PWA and safe offline behavior | Versioned icons, manifest, explicit update activation and install guidance are present. The service worker caches only the generic offline shell and versioned public icons. Optional own-card summaries are off by default, bounded to 20 cards/1 MiB and 24 hours, and removed on opt-out, logout or account switch. Browser tests inspect the actual Cache API and IndexedDB on desktop and mobile. Value actions stay online. |
| Device registration and user isolation | A foreground Firebase challenge must be acknowledged in the same verified session before the device becomes active. Tokens are encrypted at rest. The service worker checks installation and binding generation before showing or opening a notification; logout/account switching clears local bindings and revokes server registration. Denied browser permission leaves the card route usable and the retry control available in desktop/mobile browser tests. The prior Phase 0 staging check proved a real foreground challenge/acknowledgement. Phase 5 adds staff-only test-device registration and a bounded five-per-hour test path. |
| Offers and fulfillment | Owner/authorized manager drafts support informational, discount and treat kinds, branch and recipient scope, accepted images, validity and immutable published terms. Customer inbox/detail hide other members' private offers, provide claim and short-lived QR/code presentation, and distinguish claim from fulfillment. Staff validates branch/member/time and commits a discount with the authoritative paid eligible amount or a no-minimum treat without a purchase. One claim fulfills once; history remains private after expiry. |
| Campaigns and metrics | Composer includes destination, recorded branch affiliation, four audiences, schedule/expiry, audience estimate, staff-only test send, pause/resume/cancel, duplication as draft, and report counters. Snapshot and per-device dispatch use outbox/pg-boss with a fresh consent, expiry, status, token, quiet-hour and frequency-cap check before FCM. Provider acceptance, failed/unknown sends and observed clicks are separate. One member with two devices stays one audience member. No consent produces an explicit zero audience. |
| Reward, inactivity and birthday automations | Versioned rules and run history cover committed reward balance crossings, one inactivity send per qualifying-purchase episode, and one recipient-private birthday offer per business/member/year. Birthday generation does not depend on push permission; push respects a separate preference. Business-local birthday windows catch up after an outage without extending validity. Quiet hours and business/platform caps apply to eligible sends. |
| Local and hosted verification | 97 real PostgreSQL integration checks, 46 unit checks, 40 desktop/mobile Playwright checks, lint, typecheck and production build passed. A synthetic hosted Auth/PostgREST/API/browser run verified offer isolation, claim intent, zero-consent audience and campaign cancellation, then archived its cafe and removed its users. |
